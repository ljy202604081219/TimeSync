- **③主责**：数据库适配、运行环境、云部署、安全依赖、Web认证、设备凭据、限额、日志和持久化验收。

- **④协作**：按冻结的读取契约实现设备请求、缓存、HTTPS与失联处理。
- **⑤协作**：硬件采购资料、版本及后续实物验证；当前硬件尚未购买，首阶段只读显示，无按钮、触摸或日程写操作。

## 3. 冻结架构与职责边界

```text
电脑/手机 ── HTTPS ──┐
                    ├─ Render：FastAPI + 前端静态产物
```

保持同源 `/api`，复用当前React与FastAPI；本轮不增加Redis、Celery、MQTT、WebSocket、对象存储或独立前端托管。截图当前只用于识别，确认后的结构化内容入库；若以后需要保存原始图片，再单独提出需求。

首版按**单实例、单Uvicorn worker**验收，保留现有进程内写锁的边界。多worker/多实例需要另做数据库锁与并发方案，不能直接扩大运行规模。

## 5. B1：SQLite到PostgreSQL的最小适配

1. 添加兼容的Psycopg驱动并锁定实际验证版本；SQLAlchemy连接串采用 `postgresql+psycopg://...`，真实值放Secret。
2. 保留SQLite分支的外键/WAL配置；PostgreSQL使用正常事务入口，替换SQLite专用 `BEGIN IMMEDIATE`。进程内写锁在首版单worker内继续使用。
3. 保持 `RequestRecord(owner_id,key)` 唯一性、请求指纹和原响应语义。同键同内容返回原结果，同键不同内容409；失败事务不能留下半条任务、半个会议或部分成员计划。
4. 校验外键、JSON、空值、自引用版本/会议关系和时间字符串往返。首版沿用规范化ISO8601字符串，不同时重写整套时间字段。
5. 接入小规模连接池与失效连接检测；池大小、超时和Neon连接方式由实测确定，不依赖未核实的并发上限。
6. 对快照、版本和并发行为回归：当前部分查询未显式排序，PostgreSQL读取顺序变化可能影响快照稳定性；③提交复现，①确认业务侧稳定排序修正。
7. 新云库创建schema与合成身份；已有库变更使用版本化迁移脚本，保留备份与回退路径。不得通过每次启动 `drop_all()` 或重置数据实现迁移。

### 云端初始化

- 独立初始化四个合成演示身份；运行身份/会话保存在PostgreSQL，不依赖云端临时目录中的令牌文件。
- ①提供演示场景及相对日期要求，③实现受控初始化入口；数据日期应覆盖实际演示日，避免固定旧日期导致“今天暂无日程”。
- 需要课程、任务、可用时间和计划时，显式初始化合成夹具；不恢复用户已经清理掉的本机演示数据。
- 云端初始化不导入本机12条真实上传课程，不上传SQLite和私人备份。

### 必须通过的数据库用例

普通排程、DDL不可行、固定冲突、依赖、突发修复、硬约束复查、共同空档/无共同空档、会议全员确认/拒绝/改期、个人计划联动、跨用户拒绝、并发同键只创建一次、同键不同内容409，以及失败无部分提交。

## 6. B2：Web会话与设备认证

### 6.1 竞赛沙箱的Web入口

当前 `/api/demo/accounts` 不能直接作为公网登录。关闭该入口时，必须同时交付②可接入的替代入口，避免只设置 `DEMO_MODE=false` 就失去登录方式。

主方案：仅针对合成A/B/C/D的**短时沙箱会话**。服务端生成高熵不透明令牌，数据库保存哈希、身份、权限、到期与撤销信息；前端处理到期401并重新进入沙箱。不要把永久用户令牌换个接口继续公开。

会话只允许操作共享合成账号的数据，不能配置模型、管理设备凭据或做全局数据重置。页面明确“共享演示沙箱，其他体验者可能修改同一份合成数据”；正式私人用户系统不在此首版范围内。

建议新增 `POST /api/sandbox/sessions`，以及独立的会话实体/鉴权模块。**该路径和实现当前均不存在**，需③与①②冻结请求、响应和登录UI对接后再实现。

### 6.2 设备复用agenda，补权限而不另造日程接口

保持 `GET /api/v1/agenda` 的业务响应与ETag。新增设备身份只用于选择绑定owner及验证读取权限；排程、课表和会议查询继续复用现有实现。

建议的设备凭据记录：id、owner_id、token_hash、scope、expires_at、revoked_at、created_at、last_request_at。scope固定为 `agenda:read`，原始令牌只在签发时返回一次。字段为待实现设计，不是当前数据库已有实体。

| 待新增的管理接口 | 权限及用途 |
|---|---|
| `POST /api/admin/device-tokens` | 私有管理员签发绑定owner的只读凭据；沙箱访客不能调用 |
| `DELETE /api/admin/device-tokens/{id}` | 私有管理员撤销；旧凭据下一次读取即失败 |
| `GET /api/devices` | 经授权的Web查询设备最近请求等脱敏元数据；不返回token/hash或其他人的设备信息 |

以上是建议冻结的接口，当前均未实现。③应在OpenAPI及合成样例中明确其权限与错误语义，再交给②④。

- 设备令牌不能被一般业务鉴权当作完整用户身份使用；用它调用任务、会议、AI、设置或管理接口必须拒绝。
- 推荐竞赛凭据默认7天到期、可提前撤销；实际有效期由③交付说明写清。模拟短时到期来测试，无需等待7天。
- ④通过USB等可信本地配置写入可替换凭据，不将个人登录令牌或MiMo Key编译进固件。NVS存储不自动等于加密，不能声称具备未验证的物理防提取能力。
- 每次读取都验证到期/撤销，鉴权先于304判断。设备请求元数据不应改变agenda内容revision。
- `last_request_at` 只能表示服务器最近收到请求，不能证明屏幕已亮或内容已成功绘制。没有设备回执时，②不显示未经证实的“屏幕同步成功”。

硬件首阶段只读；不增加设备会议确认、触摸写入、任务修改或按钮接口。

## 7. B2：密钥、依赖、上传与AI预算

### 密钥与配置

已有环境变量继续复用：DATABASE_URL、DEMO_MODE、AI_PROVIDER、AI_BASE_URL、AI_MODEL、AI_API_KEY。MiMo Key仅放平台Secret，不进入前端环境变量、JSON响应、日志或固件。

云端关闭本机AI设置入口，或保持当前拒绝远程访问的限制；②隐藏不适用的配置按钮。云端是否启用沙箱需新增明确配置，不能假装现有DEMO_MODE同时解决了会话和权限问题。

管理员凭据、会话TTL、设备TTL和调用预算等若需配置，③更新 `.env.example` 及运行说明；新增变量均为拟实现项，模板不能放真实值。

### 兼容升级

依据此前审计处理FastAPI/Starlette安全组合，更新直接依赖与锁文件，并检查multipart等上传相关依赖。不要跳过FastAPI约束单独硬升Starlette，也不要在没有回归证据时写“安全修复完成”。保留SQLAlchemy/OR-Tools及原生依赖在目标Linux上的实际安装结果。

### 调用与体积保护

- 总请求体限制需在multipart完整解析前生效；现有读取后6MB校验不能作为全部上传保护。继续保留文件内容和字段校验。
- 为AI请求设置全局日预算、每会话/来源频率限制和并发限制。可先以全局20次图像提取/天、单并发作为评估起点，最终值由③根据账户余额与演示人数确认，不代表已有免费额度。
- 预算计数要能跨重启保留，不能仅靠随时清空的进程变量；匿名访客换会话也不能绕过全局预算。
- 远程调用前用短事务预占额度，调用后记录结果；避免在等待模型的整段时间内占住数据库写事务。
- 配额不足返回明确的429及重试提示；上游超时、非法JSON或识别失败返回安全错误与手动录入路径，不自动伪装成真实AI成功。
- 记录时间、路径、状态码、耗时和脱敏错误类型；不记录Authorization、Key、完整DSN、原始截图及模型完整请求。

## 8. B3/B4：构建与Render配置

主方案是多阶段Docker构建：Node构建前端，Python运行FastAPI。③实施时应做到：

1. 前端沿用现有锁文件，锁定实际验证的Node/pnpm版本。清理 `pnpm-workspace.yaml` 中 `esbuild: set this to true or false` 这一未定值；验证干净安装。现有启动器使用 `--ignore-scripts`，复用该策略前需确认目标Linux的esbuild可正常运行。
2. 使用适合OR-Tools预编译依赖的常规Linux Python环境，先验证Python 3.12组合；不为缩小镜像擅自改成未经验证的musl/Alpine环境。
3. 保留项目路径关系：`backend/app/` 与 `frontend/dist/` 位于同一项目根目录。FastAPI挂载静态目录依赖这个相对结构。
4. 在构建阶段完成TypeScript和Vite，运行时不安装前端依赖、不联网重建。`.dockerignore` 排除 `.env`、令牌、数据库/备份、依赖目录和无关私人文件。
5. 从backend目录启动，首版1个worker。以下仅为未来容器启动命令示例，本次未执行：

```sh
exec python -m uvicorn app.main:app --host 0.0.0.0 --port "${PORT:-8000}" --workers 1
```

启动脚本需实际展开PORT；Docker的exec数组不会自动展开 `"$PORT"`。Render要求监听0.0.0.0及指定端口，并提供平台子域名；参考 [Render Web Service文档](https://render.com/docs/web-services)。

6. `DEMO_MODE=false` 关闭原始演示凭据入口后，使用B2实现的沙箱登录与B1初始化的合成身份；相关新增开关按最终实现填写。
7. 设置Neon连接串与TLS要求、MiMo配置和管理Secret。选择两平台可用且相近的地域，具体地域和账户权限待③在控制台确认。
8. 配置现有 `/api/health` 作为存活检查；另做数据库连通与schema就绪验证，不能把现有health=ok当作数据库正常的证明。

### 免费方案的实际边界

Render免费服务闲置15分钟后休眠，唤醒约1分钟；重启/重部署/休眠会丢失本地文件修改，因此不能把线上SQLite或令牌文件当持久化存储。参考 [Render免费限制](https://render.com/docs/free)。

Neon当前Free列出每项目每月100 CU-hours、1GB存储，并可闲置休眠；不是无限资源保证。持续30秒轮询可能使数据库保持活跃，③④应区分演示期间与非演示期间频率并监控额度。参考 [Neon当前定价及免费额度](https://neon.com/pricing)。

目标是在免费额度内实现零托管费；MiMo调用费用另算。演示前正常打开页面并验证服务，准备冷启动等待提示及离线备选，不依赖额外保活组件或承诺随时无延迟。

## 9. 本地与云端联调

本地ESP32请求应指向电脑的局域网地址，不能使用设备自己的localhost。当前启动器只监听127.0.0.1；由③在可信测试网络提供专用监听入口与访问权限。不要为了联调开放公网端口或关闭证书校验。

云端改用平台HTTPS Base URL，路径继续 `/api/v1/agenda`。④完成证书验证、校时、超时和恢复，凭据单独配置。③在硬件到货前用HTTP客户端完成同一凭据的模拟请求；模拟通过与实物通过分别记录。

| 场景 | 验收要求 | 协作 |
|---|---|---|
| 登录与身份 | 原永久凭据不再公开；沙箱会话过期后失败；越界数据与管理操作被拒绝 | ③②，①评审 |
| 设备权限 | 只读agenda成功；其他业务写入/AI/设置拒绝；到期与撤销立即生效 | ③④，②复测 |
| JSON与缓存 | 空数据200、有效数据200、未变304；304无JSON体；缺字段/请求失败不被显示为空安排 | ③④ |
| 计划与会议 | Web修改后下一次读取反映变化；stale/repair_needed正确；会议全员确认才进入确定日程 | ①③② |
| 持久化 | 新建任务/会议后重启或重新部署仍存在；身份、设备凭据及限额不丢失 | ③② |
| AI故障 | 配额耗尽、上传超限、上游超时、非法JSON、空证据都有明确结果；不泄密、不部分保存 | ③①② |
| 冷启动/断网 | 不把服务唤醒或网络故障显示成“无日程”；恢复后自动重新读取；实物部分待到货 | ③④⑤ |
| 备份恢复 | 能将脱敏合成库备份恢复到隔离环境，说明部署版本与schema回滚的兼容关系 | ③，①接收 |

性能数据目前待实测。可将“预热后Web提交成功至设备模拟客户端更新不超过45秒”作为30秒轮询下的验收目标；冷启动单独记录，不把该目标写成既有实测结论。
